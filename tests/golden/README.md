# Golden data

Golden data is the behavioural oracle produced by Crystal-Builder. It is
generated deliberately, reviewed as a diff and never regenerated by CI
(Task 0.9.5).

## Phase 1

`phase-1/` was generated from `tests/corpus/` with:

```bash
.venv/bin/python scripts/golden/generate.py
```

The generator records the Crystal-Builder commit, the Python, NumPy, SciPy,
gemmi and spglib versions, and the options in every file. The current source
commit is recorded in `tests/corpus/PROVENANCE.md`.

Each JSON file contains:

| Field | Meaning |
|---|---|
| `source` | corpus-relative CIF path |
| `sha256` | digest of the CIF used |
| `versions`, `options` | exact generator environment |
| `features` | features produced in this file |
| `skipped_features` | features deferred to later phases |
| `formula`, `space_group`, `n_sites` | structure summary |
| `cell` | lengths, angles, volume and lattice matrix |
| `sites` | asymmetric-unit sites with occupancy and Wyckoff label |
| `p1` | expanded P1 atoms, labels, occupancies and multiplicities |
| `supercell` | 2x2x2 or 1x1x1 cell when it stays under the atom limit |
| `slab` | (1 0 0) slab for structures under the slab limit |
| `bonds` | perceived bonds with image, distance and order |
| `rings` | ring paths with atom index and lattice image |
| `groups` | functional-group counts and atom indices |
| `measures` | reference distances and angles |

A feature that is too large or cannot be computed is stored as
`{"error": {...}}` or `null` instead of aborting the corpus. The malformed
edge case stores a normalized parser error.

## Later phases

`space-group-dataset`, `wyckoff-letters`, `k-path`, `pxrd`, `uff`, `charges`,
`porosity` and `topology` are listed in `skipped_features` for every file and
are generated when their phase starts. The generator grows one feature module
per phase; it never rewrites the format of an existing field.

## Regeneration

1. Change the generator or the reference environment deliberately.
2. Run it in a virtual environment with Crystal-Builder installed.
3. Review the diff (values, versions, options and the source commit).
4. Commit the generator change and the data together, with the reason in the
   commit message.
5. Never regenerate in CI; the tests read the committed files.

Tolerances are in [`docs/algorithms/validation.md`](../../docs/algorithms/validation.md).
