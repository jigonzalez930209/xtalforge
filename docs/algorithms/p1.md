# P1 expansion with provenance

## Problem

A CIF or a builder stores only the asymmetric unit. Every drawing, bond search
and measurement needs the whole cell, and an edit to one drawn atom must map
back to the site that generated it. The P1 expansion therefore carries
provenance, not only coordinates.

## Formulation

For site `s` and operation `o` with integer rotation `R_o` and fractional
translation `t_o`:

```
base = R_o x_s + t_o
floor = floor(base)
frac = base - floor
tau = -floor
```

The stored atom satisfies `frac = o.apply(x_s) + tau`, where `tau` is an
integer lattice shift. All arithmetic is in fractional coordinates; the
lattice is applied only when a Cartesian position is needed.

Duplicate images arise on special positions. The expansion keeps the first
image and drops a later one when it has the same element and its periodic
distance is within the tolerance (default `0.05` Angstrom). The resulting
count is the Wyckoff multiplicity for a well-formed file.

## Complexity

`O(n_sites * n_ops * n_atoms)` with a linear duplicate scan; the corpus
structures are small enough. A hash keyed on rounded fractional coordinates
can replace the scan if profiling asks for it.

## Caveats

- The explicit operation list is the source of truth. The Hall symbol is
  stored; `detect_symmetry`/`set_space_group` can replace the operations from
  moyo when a caller wants the detected setting.
- A file that lists the whole cell under a non-P1 group produces duplicates;
  they are dropped by the periodicity filter. The CIF reader records
  `symmetry_warning` when an H-M symbol has no operation loop.
- `tau` is the shift that brings the image back into `[0, 1)`; it is not the
  periodic image used by a neighbour search.

## Validation

`crates/xtalforge-core/tests/p1.rs` covers triplet parsing, composition,
inversion, provenance consistency, special positions and the identity case.
The corpus comparison with Crystal-Builder is Task 1.6.4 and runs when the CIF
reader lands.
