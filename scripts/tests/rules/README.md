# Rule-check fixtures

`scripts/tests/run-rules-selftest.sh` copies these files into a temporary tree
under their real extensions and runs `scripts/check-rules.sh` against it.

The `.fixture` suffix keeps the samples out of the normal repository scan: the
negative cases contain warning-suppression attributes on purpose.

| File | Expected result |
|---|---|
| `pass_docs.md.fixture` | pass; ordinary documentation is not scanned for Rust attributes |
| `fail_allow_dead_code.rs.fixture` | fail; `#[allow(dead_code)]` |
| `fail_expect_unused.rs.fixture` | fail; `#[expect(unused_variables)]` |

The line-count cases (exactly 500 lines and 501 lines) are generated by the
runner so the repository does not carry two large dummy files.
